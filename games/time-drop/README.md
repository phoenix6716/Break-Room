## Scoring v1
Each event snapshot contains a year, earliest/latest accepted years, title, explanation, topic and HTTPS source. BCE/CE counting has no year zero. An exact accepted year earns 1,000 points. Approximate intervals award full credit inside the range; errors are measured from the nearest endpoint. Outside the interval, points = max(0, round(1000 × (1 − distance / allowance))). Allowance is fixed by event era: BCE 500 years; 1–999 CE 250; 1000–1699 150; 1700–1899 100; 1900 onward 50. Scoring never changes with the current year. New version 2 Dailies have five events and a native score of 0–5,000; Arcade score is native points / 50. Original version 1 ten-event snapshots retain all progress, their 0–10,000 native scale and points / 100 conversion. Completed and unfinished old saves are never shortened or regenerated. Bullseye means an exact, precise year; approximate accepted intervals say In range. On the dot requires every precise exact year in that run. Completed zeroes count; partial and practice records do not.

## Content and rotation
The authoritative source is `content/time-drop-events.json`, generated with `node scripts/build-time-drop-events.cjs` into `events.js`. Its 330 distinct event slots include all 128 reviewed Prior events copied into new Time Drop snapshots; the original Prior files are unmodified. The 202 addition slots broaden time periods, regions, science, literature, games and sport; 38 were revised after player feedback. Every event has a scoped explanation and citation. Selected new claims were crosschecked against UN, British Library, NASA and Olympic records; these checks and structural validation are not a blanket independent editorial certification of all additions. A final public-launch editorial pass remains appropriate.

A deterministic era-stratified deck assigns all events to 66 sets of five, with at least three topics per Daily in deck v2. Consecutive 66 Sydney dates exhaust the deck without repeating individual IDs, including across the cycle boundary. Bank order does not change selection. The epoch is 23 October 2026, repeated every 66 dates. Additional content must use a deliberate deck version; active/historical snapshots must never be regenerated. Unknown historical years must use explicit intervals rather than invented precision.

## Saves and practice
`break-room:time-drop:daily:YYYY-MM-DD` stores version 2 / scoreVersion 1, Sydney day, five event snapshots, current round, guessed year, committed picks, phase and edits. The first lock is final. All picks count as completed before opening the summary. Save on each valid input, submission and advance. Reload and mode switching retain the state. Cross-tab actions check newer progress before writing. Malformed existing saves remain untouched with a visible recovery message. Unavailable storage falls back to page memory with an honest warning.

Unlimited uses a sessionStorage namespace per guest/account owner. It resumes in the same tab across reload/mode switches, keeps session points/count and a seen-ID deck, and never enters cloud/Daily history. It excludes today's Daily IDs (five for new runs, ten for retained v1 runs). Mixed/topic and period settings apply next event; an empty filter combination falls back to mixed rather than stranding play. A full eligible deck is reshuffled, avoiding an immediate repeat when possible, so play continues indefinitely. No record is imported from prototype `timeDropDailyV2`/`timeDropBestV2` keys. Prior records are not converted.

## Shared integration
Use the canonical Stake shell, left menu, centred title/stats/tools, Daily/Unlimited tabs, Sydney reset rail, ? help only, trapped Help/Stats dialogs and universal footer. Original era-changing artwork is retained from the archived owner prototype; the oldest artwork is labelled Early history. There is no fake sound toggle. Profile preserves native points and Arcade score; Friends returns only completed private derived scores through the existing opt-in RPC.

Projects already running Time Drop apply `supabase/time-drop-five-rounds.sql` for five-round support. Existing live projects without Time Drop apply current `supabase/time-drop.sql` after the complete Inner Clock/player-feedback update; updated `supabase/inner-clock.sql` is the complete alternative. Fresh projects use current setup then friends. The SQL helper independently validates snapshots and reconstructs scores; its execution is revoked from browser roles. Existing saves, RLS, relationships and sharing are preserved.
